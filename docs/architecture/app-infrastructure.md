# App infrastructure

## Networking layer ([services/api/](../../services/api/))
- [apiClient.js](../../services/api/apiClient.js) reads `baseUrl` at request time and attaches the current bearer token. Its response interceptor refreshes on ordinary **401** responses, sharing one refresh across concurrent requests; ordinary **403** responses pass through to callers. Refresh expiry requires a terminal credential rejection. `gauth.create_refresh_token` relays every non-200 answer from Frappe's OAuth server as 401 `{ data: "<upstream body>" }`; only a relayed `DoesNotExistError` (unknown/revoked token), terminal authentication exception or `invalid_grant`/`invalid_client`/`unauthorized_client` ends the session, while gateway pages, empty bodies and other exceptions are transient. Network failures, 5xx responses without a terminal authentication exception, and generic refresh 403s retain the session without an attempt ceiling. `saveTokens()` persists rotated credentials before updating memory. See [sessionResilience.test.js](../../__tests__/sessionResilience.test.js).
- Set header **`x-skip-auth: "true"`** to bypass the auth header AND the refresh logic — used for `generateToken`. `plainAxios` is a separate bare instance used by token refresh, FCM, and the mobile hand-off's employee-policy download (no interceptors). SDK calls use `mobileAuth.service`'s `expo/fetch` transport, not Axios. Both sign-in methods retain the existing `apiClient` refresh path; SDK refresh-token compatibility still requires staging verification.
- **Convention:** services obtain current request context through [authHelper.js](../../services/api/authHelper.js) or direct AsyncStorage reads and often build absolute URLs. Do not memoize tenant/token/employee context across requests or alter the provisioned URL's scheme. Follow the relevant service's payload, response, and error contract; attachment uploads using `fetch()` bypass Axios interceptors.
- [index.js](../../services/api/index.js) exposes named exports and a default namespaced API (`api.attendance.userCheckIn`, etc.); some services are imported directly. Preserve existing import contracts when changing domain modules.
- Token redaction and server-message parsing helpers live in `apiClient.js`. Request/error diagnostics omit arbitrary bodies; ordinary requests only receive session credentials for the active tenant, and retries retain their authentication generation. FCM, employee/location and attachment diagnostics use counts/status metadata rather than tokens or payload dumps. Keep new logs free of credentials and private employee data; this does not establish that every third-party/native diagnostic is sanitized.

## State (Redux Toolkit + redux-persist)
[redux/Store.js](../../redux/Store.js) persists the **entire** root reducer to AsyncStorage (key `root`). A failed rehydrate restores the signed-out initial state and then persists it, so rehydration has no timeout and, outside the foreground, retries reads that iOS data protection refuses (a geofence/push launch before first unlock); see [sessionPersistence.test.js](../../__tests__/sessionPersistence.test.js). [RootReducer.js](../../redux/RootReducer.js) lists the slices, including automatic attendance and feature settings. `clearStore()` dispatches sign-out and `REVERT_ALL` to reset Redux; this is separate from durable attendance records. React Query, provided in `App.js`, handles server query caches in hooks such as [useRequestHistory.js](../../hooks/useRequestHistory.js).

Feature availability uses the existing scoped `FeatureSettingsSlice` for UI and execution. [capabilityPolicy.js](../../services/capabilityPolicy.js) checks current persisted tenant/employee and auth generation before feature operations; [capabilityRequests.js](../../services/api/capabilityRequests.js) maps transport requests and retries. Explicit denials survive failed/malformed/partial refreshes. Unknown fields retain legacy compatibility, except automatic attendance, which is off unless tenant `geo_tagging` is `true`. See [the capability audit](../capability-enforcement/00-AUDIT_SUMMARY.md) and [matrix](../capability-enforcement/01-FEATURE_MATRIX.md) before adding feature paths. New services need a boundary guard and request mapping; a hidden tile is insufficient.

## Navigation ([navigation/](../../navigation/))
`Navigator` swaps `AuthNavigator` ↔ `AppNavigator` on `isLoggedIn`. **Navigation from outside React** (FCM handlers, interceptors) must go through [rootNavigation.js](../../navigation/rootNavigation.js): `navigateSafely(route, params)` checks readiness and queues a pending navigation if the tree/route isn't mounted yet, flushed by `NavigationContainer`'s `onReady`/`onStateChange`. Route names contain spaces (e.g. `"Attendance action"`, `"Leave request"`) — match them exactly.

[AuthNavigator](../../navigation/auth-navigator.jsx) awaits [readInitialAuthRoute](../../utils/provisioning.js) before mounting the stack. Complete QR provisioning (`baseUrl` + `api_key` + `app_key`) opens `"login"` first. Otherwise, `auth_method: "mobile"` with stored `baseUrl` or `backendUrl` opens the exact route `"mobile login"` when crypto is available; the fallback is `"welcome"`. `readProvisioning()` retains its QR-only contract. `backendUrl` is a mobile preference, while `baseUrl` remains the canonical tenant read by authenticated services; clearing the preference must not resurrect it from QR storage.

## Push notifications ([services/notifications/fcm.service.js](../../services/notifications/fcm.service.js))
Uses `@react-native-firebase/messaging` (modular API). `registerBackgroundMessageHandler()` is called at module load in [App.js](../../App.js); `FcmBootstrap` runs `initializeFcm()` **only when logged in** and tears it down on logout. The service handles permissions (incl. Android 13 `POST_NOTIFICATIONS` and iOS APNS registration), token persistence, foreground/background/opened/initial-notification routing, backend token registration, **topic subscription sync** (diffed against `fcm_topics` in AsyncStorage via [utils/fcmTopics.js](../../utils/fcmTopics.js)), and unread-count sync into Redux. The backend registration method is configured in `app.json` → `expo.extra.fcmRegistrationMethod`.

## Crash reporting ([services/crashlytics.service.js](../../services/crashlytics.service.js))
Firebase Crashlytics, pinned with RNFB app/messaging. Native crashes and uncaught JS errors are captured automatically; [firebase.json](../../firebase.json) enables collection in release builds only. The service is the only importer and requires the package lazily inside `try/catch`: the package creates its native module on import, so a static import would crash binaries built before it when they receive this JS over OTA. Every export is a no-op there. `App.js` initializes it first. [CrashReportingBootstrap](../../components/CrashReportingBootstrap.jsx) sets a hashed employee ID plus tenant/auth/UI-mode keys from `isLoggedIn` and clears them on sign-out. The navigator records the current route. [ErrorBoundary](../../components/common/ErrorBoundary.jsx) wraps only `<Navigator />`, so the bootstraps keep running, and reports render errors; React Native sends caught render errors to ExceptionsManager, not the global handler. Report only unexpected failures. At mixed catch sites, `isProgrammingError` keeps network, server, permission and validation failures out. Keep `crashlytics_javascript_exception_handler_chaining_enabled` on: RNFB 24's handler ignores the `fatal` flag, so turning chaining off would terminate the app on non-fatal reports. The Profile test actions render only on development and `preview`-channel builds.

## Styling
NativeWind via `nativewind/babel` supports `className` on RN components; content globs are defined in [tailwind.config.js](../../tailwind.config.js). Reuse [constants/theme.js](../../constants/theme.js) for design tokens and [useAppTheme.js](../../hooks/useAppTheme.js) for the active palette, so themed components respond to appearance changes.
