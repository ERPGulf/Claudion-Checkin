## Capture, replay, and registration

| ID | Confirmed mechanism and evidence | Potential consequence / condition |
| --- | --- | --- |
| R01 | Native persistence is one last-event slot; emissions require a listener. [Android store:57](../../modules/expo-auto-attendance/android/src/main/java/expo/modules/autoattendance/GeofenceStore.kt#L57), [iOS store:46](../../modules/expo-auto-attendance/ios/GeofenceStore.swift#L46). | ENTER then EXIT while JS is absent retains only EXIT. A closed local session can skip that EXIT, losing the entire shift. No durable native journal exists. |
| R02 | Listeners attach before registration; registration precedes replay and can emit initial ENTER. [bootstrap:355](../../components/AutoAttendanceBootstrap.jsx#L355), [startup:629](../../components/AutoAttendanceBootstrap.jsx#L629). | Initial ENTER can overwrite an older saved EXIT before replay reads it. Exactly which callback wins is OS/timing-dependent. |
| R03 | `ensureMonitoring` resolves fresh office metadata but skips `startGeofence` when stored monitoring is true; cleanup on employee change removes listeners without stopping the old fence. [bootstrap:442](../../components/AutoAttendanceBootstrap.jsx#L442), [cleanup:643](../../components/AutoAttendanceBootstrap.jsx#L643). | Fence geometry can stay tied to an old office/employee while requests tag a newly resolved office. Same-code tenant changes are absent from auto-effect dependencies. |
| R04 | Replay is scheduled after the permission/office initialization attempt. Highest-GPS acquisition has no timeout/cache fallback; caught errors/denied permission return null and still allow replay. [bootstrap:442](../../components/AutoAttendanceBootstrap.jsx#L442), [office:191](../../services/api/attendance.service.js#L191). | Stalled position acquisition can delay replay past available execution time. Handled offline/GPS/permission failures do not prevent replay, but prevent inside-presence recovery when no office is resolved. Limited iOS wake time compounds delays. |
| R05 | Global processed timestamp has no tenant/employee/event-ID scope; replay expires after 24 h or >60 s future; live listeners bypass these filters. `markEventProcessed` is read-then-write, not atomic. [event log:24](../../utils/geofenceEventLog.js#L24), [event log:52](../../utils/geofenceEventLog.js#L52), [event log:90](../../utils/geofenceEventLog.js#L90), [bootstrap:355](../../components/AutoAttendanceBootstrap.jsx#L355). | Older events can be swallowed across identities; equal timestamps collapse; a future expired mark can suppress later replay; concurrent writes can regress the mark. Delayed live EXIT can close a newer session or precede its start. |
| R06 | Native event timestamp is callback receipt time; events omit identity/policy/source-position metadata. Warnings-only decisions use current policy. [Android receiver:55](../../modules/expo-auto-attendance/android/src/main/java/expo/modules/autoattendance/GeofenceBroadcastReceiver.kt#L55), [Swift manager:227](../../modules/expo-auto-attendance/ios/GeofenceManager.swift#L227), [bootstrap:224](../../components/AutoAttendanceBootstrap.jsx#L224). | Delayed delivery changes recorded time; replay after login/policy change cannot establish who crossed or which policy applied then. |
| R07 | Only one nearest-center office is registered; no dwell/debounce/hysteresis. Authoritative and display coordinate priorities differ. [attendanceLocations:110](../../utils/attendanceLocations.js#L110), [autoAttendance:53](../../utils/autoAttendance.js#L53), [Android manager:97](../../modules/expo-auto-attendance/android/src/main/java/expo/modules/autoattendance/GeofenceManager.kt#L97). | Another valid office may be unmonitored; unequal overlapping radii can make nearest-center selection miss an eligible office. Boundary noise may alternate IN/OUT. A displayed name/position does not prove current native geometry. |
| R08 | Inside-presence recovery can submit IN after manual OUT without a new crossing; no symmetric outside-presence OUT is implemented. [bootstrap:525](../../components/AutoAttendanceBootstrap.jsx#L525), [bootstrap:606](../../components/AutoAttendanceBootstrap.jsx#L606). | Restart/toggle while inside can reopen a manually closed shift. Missing EXIT is not recovered simply by reopening outside. |

## Session, identity, and ordering

| ID | Confirmed mechanism and evidence | Potential consequence / condition |
| --- | --- | --- |
| R09 | Older native replay receives NULL source scope; enqueue retains NULL tenant if scope is absent/stale. Scoped claims cannot select it, but dependencies include older NULL rows. [bootstrap:237](../../components/AutoAttendanceBootstrap.jsx#L237), [queue service:209](../../services/offline/AttendanceQueueService.js#L209), [repository:119](../../services/offline/AttendanceQueueRepository.js#L119). | Locally accepted historical punch remains undeliverable and can hold newer same-employee rows. Attribution cannot safely be invented from the current login. |
| R10 | Bootstrap forces queue only for IN. OUT can attempt the online endpoint even when an earlier queued IN remains; queue refusal can make forced IN fall back online. [bootstrap:266](../../components/AutoAttendanceBootstrap.jsx#L266), [queue service:521](../../services/offline/AttendanceQueueService.js#L521). | Server may receive OUT before its locally accepted IN or IN before an older OUT. SQL FIFO protects rows that enter the drain, not requests that bypass it. |
| R11 | Attendance queue counts/history are employee-only; recovery/drain is tenant-scoped. [repository:1033](../../services/offline/AttendanceQueueRepository.js#L1033), [repository:1137](../../services/offline/AttendanceQueueRepository.js#L1137), [history hook:75](../../hooks/useAttendanceHistory.js#L75). | Same-code rows from another tenant can suppress presence/force queue, and employee history can display or dedupe across tenants. Recovery UI offers a stricter scoped view. |
| R12 | Session is device-global; owner compares employee code only and clears asynchronously outside the transition lock. Mobile handoff explicitly clears on tenant change; QR scan does not do so. [session:412](../../utils/attendanceSessionState.js#L412), [owner:442](../../utils/attendanceSessionState.js#L442), [mobile:303](../../services/api/mobileAuth.service.js#L303), [QR:192](../../hooks/useQrScanner.js#L192). | Same employee code in another tenant can inherit session through paths lacking tenant clear. Owner cleanup can interleave with startup replay/live submissions. Existing checkout floor and processed mark also remain global. |
| R13 | Session lock and sync single-flight are process-local. Stuck claims are released without an age lease. OUT/IN pair links use separate SQL updates. [session:174](../../utils/attendanceSessionState.js#L174), [repository:790](../../services/offline/AttendanceQueueRepository.js#L790), [pairing:229](../../services/offline/AttendanceQueueRepository.js#L229). | Multiple JS contexts or termination between pair writes can weaken serialization/pair consistency. Atomic claim itself remains a protection; normal same-process overlap is coordinated. |
| R14 | Auto bootstrap uses current employee ref and ordinary online service requests with fresh tenant/token reads; cleanup does not cancel every in-flight action. Queued requests have stronger generation/scope guards. [bootstrap:233](../../components/AutoAttendanceBootstrap.jsx#L233), [auto API:452](../../services/api/attendance.service.js#L452), [cleanup:643](../../components/AutoAttendanceBootstrap.jsx#L643). | An identity switch across awaits could mix an event/employee with newer credentials/tenant. A dispatched request cannot be recalled. Actual server acceptance is unknown. |
| R15 | Queue counts fail open to zero; unavailable server status with empty relevant queue permits presence IN. Durable read errors return closed. [bootstrap:203](../../components/AutoAttendanceBootstrap.jsx#L203), [bootstrap:606](../../components/AutoAttendanceBootstrap.jsx#L606), [session:144](../../utils/attendanceSessionState.js#L144). | Storage/status failure can make safety guards less conservative and allow another online IN. Backend uniqueness must be verified rather than assumed. |

## Native races and platform unknowns

- **Confirmed mechanism:** iOS stop cancels initial retries but leaves pending start; a later matching registration-success delegate can save monitoring and request initial state. Same-identifier retries lack a registration generation. **Potential consequence:** opt-out/start replacement timing can resurrect bookkeeping or produce a late ENTER. [Swift manager:194](../../modules/expo-auto-attendance/ios/GeofenceManager.swift#L194), [Swift manager:253](../../modules/expo-auto-attendance/ios/GeofenceManager.swift#L253).
- **Confirmed mechanism:** Android add/remove are asynchronous, storage changes on completion, and auto inactive-stop is outside startup promise serialization. **Potential consequence:** start/stop completion ordering can disagree with current opt-in; failed removal can leave stale monitoring. [Android manager:120](../../modules/expo-auto-attendance/android/src/main/java/expo/modules/autoattendance/GeofenceManager.kt#L120), [bootstrap:149](../../components/AutoAttendanceBootstrap.jsx#L149).
- **Confirmed mechanism:** native monitoring/error queries rely on bookkeeping and do not repair registration after runtime error or permission downgrade. **UNVERIFIED:** actual delivery after GPS disable, permission restoration, Play Services unavailability, or iOS authorization changes. [Android receiver:30](../../modules/expo-auto-attendance/android/src/main/java/expo/modules/autoattendance/GeofenceBroadcastReceiver.kt#L30), [Swift manager:340](../../modules/expo-auto-attendance/ios/GeofenceManager.swift#L340).
- **Confirmed mechanism:** Android receiver saves/emits but does not start JS; boot restore is asynchronous without a worker. **UNVERIFIED:** receiver and re-registration completion across reboot, package update, user force-stop, power saver, and OEM restrictions. [Android boot receiver:13](../../modules/expo-auto-attendance/android/src/main/java/expo/modules/autoattendance/GeofenceBootReceiver.kt#L13).
- **Confirmed mechanism:** iOS runtime gives its startup task a 25-second timer and sets started before root success; full JS startup can need online/config/GPS/OTA work. **UNVERIFIED:** OS wake delivery, modern force-quit behavior, Background App Refresh conditions, scene guard timing, retry after Updates failure, and completion before suspension. [runtime:46](../../ios/ClaudionCheckin/AttendanceBackgroundRuntime.swift#L46), [App.js:130](../../App.js#L130).

Platform guidance and caveats are linked in [04 Android](04-ANDROID-IMPLEMENTATION.md) and [05 iOS](05-IOS-IMPLEMENTATION.md). Those references do not validate this app on hardware.
