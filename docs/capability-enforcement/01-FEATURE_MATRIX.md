# Feature enforcement matrix

Status describes the implemented client paths after this change; the baseline is in `00-AUDIT_SUMMARY.md`. **Enforced** means covered by application execution guards and regression tests, not verified backend authorization or device behavior. “N/A” in a cell means that feature has no corresponding path. Unknown fields retain the explicit compatibility policy in `02-CAPABILITY_ARCHITECTURE.md`.

Follow-up scope qualification: [07](07-FINAL_GAP_ANALYSIS.md) records the ownership, callback, legacy replay and R4 fixes. Backend-confirmed tenant geo false/0/null now independently vetoes automatic attendance regardless of employee mode, through the existing centralized AUTO capability. Registration, processing, admission/final INSERT, automatic POST and 401 retry recheck this gate after awaited work. Tenant geo 1, Boolean true and missing-field semantics remain unconfirmed; no mode mapping is invented. Older unowned events remain retained without submission. Use durable native builds for controlled staging; [09](09-RELEASE_READINESS.md) retains backend/device gates.

Backend contract, 2026-10-26: `geo_tagging` is a boolean and the tenant switch, `auto_attendance` is retired, and employee `geotagging` 2 is the only monitored mode; mode 1 (warnings only) has no defined client behaviour yet. The `geo_tagging` and `auto_attendance` rows below reflect this.
